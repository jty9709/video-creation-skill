# 导出与质量复核

## 先做短验证，后做完整导出

在存在不确定性的镜头上先验证目标风格、复杂动作、快速运动和声音配合。用真实画幅与合理预览分辨率，避免预览时正确、最终画幅却裁掉主体。风险解决后继续全片；用户未要求样片时不能止步于样片。

程序工程保留确定的帧率、总时长、种子、资源版本和依赖。加载字体、图像与视频纹理后再渲染；物理/粒子模拟按固定步长或缓存复现。编码进程完成且退出成功后才能探测最终文件，不能把仍在写入的 MP4 报为成片损坏。

制作程序化快动作时，除帧率外还涉及曝光时间。按画面需要选择时间子采样或速度模糊；固定曝光窗口与采样相位，避免硬切镜头边界被无意混合。拖尾轮廓可以是一种设计，不能把它等同于真实时间采样。需要精读的字幕通常最后清晰合成。颗粒、模糊和光效强度要对照实际输出尺寸与压缩效果，不能默认全片开启同一套后处理，也不必给普通实拍重新制造模糊。

程序动画的验证点还要覆盖参数边界：入场恰好开始、关键落点及其前后、透明度/遮罩切换、镜头边界、最后一帧，以及最终启用的子帧采样时刻。渲染器对零缩放等奇异变换可能有不同限制；必要时跳过不可见对象或限制有效参数范围，不用粗暴改变动作逻辑来掩盖错误。

分别检查生成器与编码器的完成状态。日志经过管道筛选时不能让末端命令的成功掩盖渲染失败；片长、帧数和末帧仍需核对。若要并行渲染，先保证帧可独立重现、合成顺序稳定，并按内存/设备能力设并发，不盲目占满全部核心。

通用 MP4 可使用 H.264 + yuv420p + AAC + faststart，具体编码按用途与可用环境选。透明视频、HDR、竖屏平台或专业后期有不同要求，不能一律套用此组合。避免通过复制帧把低帧率动画伪装成流畅高帧率。

## 辅助检查脚本

运行 `scripts/inspect_video.py --help` 查看参数。依赖 Python 3、FFmpeg 和 FFprobe，不需第三方 Python 包。

```bash
python3 <skill-dir>/scripts/inspect_video.py /absolute/path/final.mp4 \
  --out /absolute/path/qa-final --cuts 8,16,24 --clips --expect-audio
```

- 输入为本地文件，源文件只读；输出目录必须为空或尚不存在，防止旧检查图混入新结果。
- 默认在全时长均匀抽取 12 帧（短片按帧数限制）；`--samples` 可调整。每个 `--cuts` 边界额外抽取前后约 0.4 秒、0.1 秒与切点帧。
- `--clips` 为每个边界导出前后约 0.8 秒的片段并保留首个音轨。任意关键动作也可作为 cuts 输入，用它检查落地/抓取/形变等事件。
- `report.json` 记录源 SHA-256、规格、完整解码结果、音轨情况、黑场/停帧线索及生成的帧/片段路径。扫描和片段使用首个非封面视频流及首个音轨；多音轨/多视角交付要另查其他轨道。`inspection.log` 保留扫描证据，`contact.jpg` 便于概览。
- 返回 0 仅表示技术检查和取证完成；1 表示解码、所需音轨或取证步骤失败；2 表示输入/依赖/输出目录/时间参数无效。无论返回多少，审美、含义、动作合理性和听感都没有被自动验收。
- 黑场与停帧检测是启发式：静态标题、细微呼吸、深色场景、刻意停顿可能被标记；一直移动的错误动画也可能完全不被标记。响度为空时表示未测得，不能当作静音或零值。

## 视觉与时序复看

不要只看封面或每镜头的中间帧。

先把代表性画面并排，对照 [创意开发与视觉验收](creative-development.md#先过视觉验收再扩成整片) 判断整体是否被同一个图文模板支配，并将导演依据中的情绪、空间与关键事件逐项对照实际片段，再进入局部错误检查。报告分开记录“创意与美术判断”和“技术与连续性检查”；后者全部通过也不能自动关闭用户对审美的批评。方案写了沙盘、压迫、逆转或交响高潮，并不证明这些已经出现在输出中。

| 观看方式 | 发现的问题 |
|---|---|
| 正常尺寸、正常速度看整片 | 叙事、节奏、突兀段落、过密信息、长时间无发展 |
| 大小两种观看尺度 | 主体权重、字幕可读、色彩/材质是否协调；细节是不是在抢戏 |
| 字幕切换前后及长短句抽查 | 按 [字幕规则](audio-and-timing.md#字幕断句与标点) 检查句尾多余标点、孤立短语、闪现、语义误删、换行与居中，以及字幕与实际语音是否对齐 |
| 人物面部与接触点近查 | 五官透视、眼睛/嘴型、关节、穿插、手和道具脱离、脚底滑动 |
| 所有转场与关键动作连续检查 | 瞬移、闪烁、形变、速度突变、近裁剪、错误遮挡、重拍空场 |
| 动作结束和片尾多留几个采样点 | 目标落位、结果保持、字幕提前退出、收势与声音尾音 |

画面和谐不是“没有报错”。检查主要形状、明暗、材质、线条粗细、文字与主体的关系；技术小字、粒子和光效是否淹没关键内容；写实照片与矢量角色混合是否有意且统一。角色多样性服从叙事与整体美术，不随镜头无理由换身份。

对生成帧尤其检查数量、姿态、纹理、光照和背景是否跳变。对图解核对数值、箭头、概率/总量、标签、运动方向与旁白是否一致。参考图的静态美观不证明动作自然。

把具体观察反馈到制作参数：轮廓丢失就处理背景/明度/描边/光照；运动出框就检查整个包络；动作迟钝就检查预备时间、主落点和收势；文字难读就检查字形比例、停留时间和变形相位。不要只留下“看起来不错”，也不因参考作品采用某种特效就将其加入所有后续任务。

当前代理能够实际感知播放时，正常播放和听查；仅播放器或用户界面具备播放能力，不代表代理具备感知能力。无法感知连续播放时读取覆盖全片的抽帧并加密重点时段；无法听查就记录这个限制。不要把展示了视频、提取了声音、测了响度或完整解码写成“已经完整听过/看过”。

## 修正并留下真实证据

为问题写短记录：`版本/哈希 → 时间码 → 观察到的问题 → 修正 → 复看结果`。优先修复误导内容、畸形角色、断裂动作、不可读文字和明显声画错位，再微调装饰。修复后更新成片与相关抽帧，检查相邻片段以防时序影响扩散；旧 contact sheet 不能支持新版本的结论。

即使技术测量都通过，若仍是静态插画搭配文字轮播，应回到分镜与动作设计。增加随机抖动、全屏粒子或更多切换效果不能修复缺少叙事动作的问题。

交付范围与验证范围分别说明：完整视频、预览、工程或字幕是什么；实际做过哪些检查、尚有哪些限制。不要让未验证的“电影级”“完美同步”“逐帧检查”等说法替代证据。
