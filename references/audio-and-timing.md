# 声音与时间设计

## 先决定由谁主导

主导因素可以随段落变化；下面是安排时序时的优先关系，不是按视频类型分配手法。同一段可以同时具有语义、动作和音乐锚点，取舍依据是当前内容与表达目标。

- 讲解或对白：先写适合听的文案并生成/录制，再以真实词句时长安排动作。划分语义小节，画面在关键词出现时产生相应事件，允许必要的预备或视觉提前量。
- 音乐或舞蹈：先确定可使用的音乐与结构，标记乐句、重拍、停顿、起伏和尾音，再安排主要动作与切点。不是每一拍都要切镜头。
- 叙事、纪录或氛围：按情绪与事件建立声音桥、环境声和留白；不强行添加鼓点或旁白。

音乐可以来自用户素材、可用且合适的生成能力、允许使用的素材库，或程序合成。选择符合片子质感的方式；简单合成循环不能因为“原创”就自动当成足够好的成品。不要把参考音轨、旋律或声音身份当作已授权复制的素材。

声音方向应参与导演设计，不能等画面完成后再铺一条不变的背景循环。明确哪些段落建立压力、加速、停顿、爆发或收束，并据此改变节奏密度、音色、低频、音域和空间。热血可以由整齐的行动节奏、持续推进、蓄势后的释放构成；单独提高 BPM 或音量不能保证这种感受。古代题材也不自动等于慢速五声拨弦，具体选择服从用户期望和叙事语境。

战役等有强冲突的场景，把可见事件和声场连接：集结/迫近、接触、转折、撤退各有什么声音变化，高潮前是否留出了对比，旁白是否给关键事件留出空间。不强制使用固定乐器或采样，但不能仅在每章开头敲一下鼓就声称完成了史诗声音设计。编排表或代码可以验证声音结构，实际听感仍需听查；不能从响度或“用了鼓”推断热血达标。

把主事件、动作过程和段落氛围分开安排声音角色：主事件提供可辨认的落点，过程声说明移动、摩擦、变化或空间，音乐/环境声建立整体情绪。它们可以互相留位，不要求每个对象都发声。音色、音高、声像和包络应支持动作性格；每次变化套同一个 whoosh 或强拍，会抹掉差异。段落对比可以通过减去声部、改变密度或留下空隙建立，不只靠不断加轨。

## 共用时间轴

时间表最少能连接以下信息，具体格式可沿用已有工程：

```json
{
  "start": 4.2,
  "end": 7.8,
  "event": "物体触地并弹回",
  "anticipation_start": 5.7,
  "visual_landmark": 6.05,
  "audio_anchor": {"kind": "impact", "time": 6.05},
  "settled_at": 6.6,
  "result_hold_until": 7.3
}
```

旁白词边界、句边界或人工标记必须来自最终使用的音频。换声线、改语速、加停顿或重写句子后重新对齐。字幕跟随实际表达，不整段长文字贯穿一个镜头。

固定速度音乐可以用 `t = offset + beat_index * 60 / BPM`；变速音乐用实际拍点表。自动节拍候选受人声/音效和半速/倍速影响，需要听查或可靠验证，不把算法猜测写成已知 BPM。节拍映射到最近视频帧，必要时以音频采样精度保留音效攻击点。相同的时间锚点驱动视觉与声音，避免两边各自“约在某秒”。

区分起动、接触/转折和完全稳定的时刻，并注明声音锁定哪一个。声音的起音、能量峰值和感知落点也可能不同；仅测到某个峰值靠近拍点，不能证明画面事件同步。检查最终片中事件前后的一小段，而不只比较时间表或注释。

需要严格时长或卡点时，从绝对时间推导每个帧/采样位置：`frame ≈ t × fps`、`sample ≈ t × sample_rate`。一拍或一段常常不是整数帧，不能先把每段帧数取整再不断累加；保留精确时间，统一声明帧起点/中心与取整约定。离散视频帧只能量化呈现，音频可独立保持采样精度。最终验证实际帧数、音频长度、片尾余音与关键事件，不笼统宣称任意拍点都能零误差落在帧上。

## 字幕断句与标点

- 配音文稿与字幕显示文本分开处理：配音保留帮助语气和停顿的标点；字幕沿用对应的语义与音频时间，不把显示清理回写到配音文稿，也不因删标点重新按字数均分时长。
- 普通中文字幕默认省略每条末尾的逗号、句号、分号等停顿标点，用字幕切换与实际停顿表达。比如 `陆上，` 显示为 `陆上`。内部停顿优先按完整语义拆条或换行，不直接删光标点后把多个分句粘连。
- 不按每个逗号或固定字数机械切条。结合语义、语速与可读时长组织字幕；`陆上` 这样的短语若只是下句的开头且没有独立强调，应与后文组成完整意群，避免两三个字一闪就过。长度与行数服从画幅和字号，不强设所有视频通用的字数。
- 按意思保留问号、必要的感叹号、引号、书名号，以及数字、网址、公式、代码中的符号；省略号只在确实表达迟疑或话未说完时使用。用户指定的字幕规范优先，外语字幕遵循对应语言习惯，不套中文去标点规则。此默认适用于对白/旁白字幕，不自动清理标题、图表标签和需要准确引用的原文。
- 清理显示文本后再测量宽度、换行和居中，移除残留空格，避免悬空标点、标点独占一行和删标点后的视觉偏移。同一套字幕采用一致规则；烧录字幕与另交的字幕文件来自同一份处理后的文本与时间轴，除非用户另有要求。

## 混音与声音层次

旁白清晰度优先于配乐响度。让配乐在说话时平滑压低、空隙中合理回升；调整起落速度避免抽吸感。音效服务可见事件和空间，不给所有运动都塞一个 whoosh。保留段落能量差和适当动态范围。

完整混音后测集成响度、真峰值、响度范围与时长，再听最终编码文件。流媒体解说可把约 −16 至 −14 LUFS、真峰值低于 −1 dBTP 作为试混起点，平台/用户规范与实际听感优先；不将它们作为通用通过阈值。避免各轨都归一化到 0 dB 后直接相加。

实际复核：吐字/多音字、呼吸停顿、背景是否盖过人声、声音方向是否突变、音效是否贴合动作、接缝有无爆音、结尾有无截断混响。响度数值不能验证这些。保留尾音和画面收势，不用 `-shortest` 掩盖音画长度不一致。

只需纯配乐时不强加旁白；有意静音时不强制音轨。无声音生成能力且声音是明确要求时，先完成独立可做的部分，再说明缺口，不能交付无声片并宣称任务全部完成。
