# Video Creation Skill

**仿 Claude Opus 5.5 视频效果的通用视频创作 Skill**

让 AI 根据主题完成创意构思、镜头设计、动画、声音、字幕、渲染和成片复核。重点是让内容在时间中真实发展：动作有起因和结果，镜头有空间，声音回应事件，风格由当前内容决定。

这个 Skill 从多次视频制作、失败复盘，以及用户提供的 Claude 视频制作案例中提炼经验。它借鉴的是创作与迭代方法，不依赖 Claude API，也不绑定某个模型、配色、时长或渲染库。实际效果取决于执行模型、可用工具、素材和制作投入。

## 它解决什么问题

- **减少 PPT 感**：避免常驻标题、解释段落和插图一页页轮换，也不把静态图片的平移缩放当成完成主要动作。
- **先有构想，再选工具**：根据内容、情绪、受众和约束发展镜头，而不是从熟悉的模板开始填文案。
- **动作细腻且连续**：关注准备、主动作、跟随、收势，以及角色五官、接触点、遮挡和跨镜头状态。
- **声画共同设计**：从实际旁白、音乐结构和可见事件安排时间，避免全片铺同一条循环或给所有动作套同一个音效。
- **先验证关键片段**：用真正有难度、能体现目标情绪的片段验证方向，再继续完整制作。
- **检查实际导出**：创意、美术、连续性、听感与文件规格分别复核。文件能播放、检测没有报错，不代表审美已经达标。

## 通用性来自哪里

每个段落、每个镜头都可以依据具体表达选择和组合实拍、SVG、Canvas、角色动画、三维、生成图像、动态图解、剪辑和音乐。

访谈可以卡点，纪录片可以使用三维，教学可以加入角色表演；这些都需要服务于当前内容。三维、粒子、弹性动画和视觉母题是按需使用的手法，不是所有视频的固定配置。安静、留白和静止阅读同样可以成为有效的视频语言。

## 安装

将仓库作为 `video-creation` 技能目录安装。Codex 的技能目录与发现机制参见 [官方技能文档](https://developers.openai.com/codex/skills/)。

用户级安装：

```bash
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/jty9709/video-creation-skill.git \
  "$HOME/.agents/skills/video-creation"
```

只在当前项目使用时，在项目根目录执行：

```bash
mkdir -p .agents/skills
git clone https://github.com/jty9709/video-creation-skill.git \
  .agents/skills/video-creation
```

两种方式选一种即可。已有同名技能时先核对版本与本地修改，避免重复安装。也可以下载仓库 ZIP，将解压后的目录命名为 `video-creation`，放入相应的技能目录。

## 使用

在支持 Skill 的编码代理中显式调用 `$video-creation`，描述你要制作的视频。提供主题、受众、用途、时长或声音偏好会帮助确定方向；没有指定的常规事项由代理结合上下文判断。

```text
使用 $video-creation 制作一条介绍大模型原理的科普视频，
面向没有技术背景的观众。风格由内容决定，动作要能解释原理，
需要中文旁白、字幕和配乐，交付可播放的 MP4。
```

```text
使用 $video-creation 制作三国版图变化的视频。
关键战役采用三维沙盘推演，通过地形、行军、交战和战后变化
呈现力量关系。节奏需要有压迫、蓄势和释放，说明必要的史实简化。
```

```text
使用 $video-creation 制作一条温柔的种子发芽短片。
用细小动作、光线和环境声表现生长，让画面细腻连贯。
具体风格和镜头由你设计。
```

也可以提供现有成片，要求诊断并改进。参考视频用于提炼方法；明确要求跟随的特征才成为当前任务的约束。

## 制作与交付

Skill 引导代理完成以下工作，并按任务复杂度调整过程：

1. 确定表达重点与情绪目标，选择有理由的美术和镜头方向。
2. 把内容组织成可观察的事件，安排动作、声音与镜头之间的衔接。
3. 验证代表性难点，制作所需素材并完成整片。
4. 对最终导出检查内容、画面、连续性、字幕、声音与规格，修正后重新检查。
5. 展示实际成片，按约定交付工程、字幕等文件，并如实说明验证范围。

用户要求完整视频时，分镜、代码、网页和短样片都是过程产物，不能替代约定的完整成片。用户要求画面与声音全部由代码生成时，现成图片、视频、乐器或音效采样也不能冒充代码生成素材。

## 中文字幕

普通对白或旁白字幕默认省略句尾逗号、句号等停顿标点，例如 `陆上，` 显示为 `陆上`。字幕按完整意思和真实语音断句，避免两三个字一闪而过；保留影响意思的问号、引号及数字、公式等必要符号。

配音文稿保留有助于语气和停顿的标点，显示字幕单独处理。清理文字后重新检查宽度、换行和居中；用户指定的字幕规范优先。

## 环境与工具

仓库提供创作指令、参考方法和一个检查脚本。执行代理需要能够读写工程、运行制作工具，并具有当前任务所需的素材和渲染能力。

| 部分 | 需求 |
|---|---|
| 阅读与使用 Skill | 能加载 `SKILL.md` 及关联文件的代理 |
| 随附检查脚本 | Python 3、FFmpeg、FFprobe；Python 部分仅用标准库 |
| 画面制作 | 按任务选择 SVG、Canvas、Three.js、Manim、Blender、剪辑或生成能力等 |
| 配音、配乐与音效 | 按任务选择可用的录制、合成、生成或素材工具 |

无需为了使用 Skill 预先安装所有列出的制作工具；代理应先确认实际能力，再选择生产路径。

## 成片检查脚本

在仓库根目录执行：

```bash
python3 scripts/inspect_video.py /path/to/final.mp4 \
  --out /path/to/qa-final \
  --cuts 4,8,12 --samples 16 --clips --expect-audio
```

`--cuts` 替换为实际镜头或事件时间，单位为秒。`--out` 必须是新目录或空目录；有意无声的视频省略 `--expect-audio`。其他参数使用 `--help` 查看。

脚本只读源文件，输出文件哈希、规格、完整解码结果、音量测量、可疑黑场或停帧线索、概览图，以及可选的边界片段。返回 `0` 只表示技术检查和取证完成；`1` 表示解码、所需音轨或取证失败；`2` 表示输入或依赖错误。

自动检测用于帮助定位复看，不能证明画面合理、动作自然或声音好听。代理无法实际感知整片播放或听查时，应说明检查范围，不能把抽帧、展示视频或测响度写成已经完整看过、听过。
